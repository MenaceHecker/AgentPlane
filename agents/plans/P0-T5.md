## Supervisor revision: proposed decision, not approved

### Architecture and scope

Use **one foreground Python supervisor/runner per smoke invocation**, owning both mock-model children directly. `scripts/mock-smoke.sh` becomes a small Bash-3.2-compatible wrapper that changes to the repository root and `exec`s `python3 -I scripts/mock_smoke.py`; it starts no background model or supervisor. This deliberately migrates smoke orchestration and HTTP/SSE assertions, not product/model code. A per-child supervisor plus a shell controller would add an IPC protocol and another lifecycle to stop safely; this proposal avoids both. Python3 is already a prerequisite. Preserve the existing Make entry points and local-only behavior.

New files: `scripts/lib/owned_process.py` (ownership state machine), `scripts/mock_smoke.py` (smoke runner), `scripts/tests/test_owned_process.py`, `scripts/tests/test_mock_smoke.py`. Use stdlib `unittest`, not a new dependency. Preserve `scripts/lib/owned-process.sh` filesystem helpers used by kind; retire its process signalling/reaping API and all callers when the runner migrates. Retain `scripts/test-owned-process.sh` as the entry point for the existing filesystem regression suite plus the Python lifecycle tests. Translate old process assertions to the new tests with a coverage mapping; do not just remove the canary, failure, escalation, interrupt or partial-start obligations.

No provider endpoint, HTTP shutdown endpoint, argv nonce, ps-based signalling decision, process-group signal, daemon, registry, cloud resource or dependency/toolchain upgrade is introduced. Curl may cease to be a smoke prerequisite if the stdlib client replaces it; update docs only after tests demonstrate equivalent checks. Go build remains a disclosed preflight operation outside the model shutdown deadline.

### Ownership invariant

The runner is the sole parent, waiter and signaler for its directly spawned model children. It is single-threaded; no asynchronous child watcher, background reaper, SIGCHLD handler, Popen destructor-driven reaper, `waitpid(-1, ...)`, shell wrapper around the model, or externally supplied PID may own these children. Establish SIGCHLD default disposition before spawning, explicitly avoiding SIG_IGN/automatic collection. INT/TERM/HUP handlers set a stop flag only: they do not signal, reap, raise asynchronous exceptions or spawn another child.

The library starts argv arrays without a shell and returns an opaque owned-child object. `request_stop(child)` accepts that exact object registered by this owner, not a numeric PID, name discovered through ps, or endpoint supplied by an external caller. Reject forged, foreign-owner and completed objects. The PID is private kernel-call state only. Use a low-level POSIX adapter: in this single-threaded runner, `os.fork` creates the direct child; the child resets INT/TERM/HUP and SIGCHLD dispositions, starts its own session with `os.setsid`, redirects stdin to the null device and stdout/stderr to the already-opened owned logs, closes unrelated inherited descriptors, then `os.execvpe`s the argv array. An exec/setup error writes a bounded diagnostic and calls `os._exit(127)`; the parent observes and reaps that failure, never forgetting the spawned child. Only the parent runs the ownership loop. Do not substitute subprocess/asyncio automatic waiting without revisiting the invariant. Starting a new session isolates terminal signals; signalling a group is not allowed. Verify fork/session support on supported hosts; missing support fails closed and returns to the planner, not a shell fallback.

States: NEW -> OWNED -> TERM_SENT -> KILL_SENT -> REAPED; early exit may go directly OWNED -> REAPED. Register the returned child PID before any interrupt flag is acted upon. On each normal poll, only this owner may call `waitpid(child_pid, WNOHANG)`. A returned exit status transitions to REAPED and disables all future signals **before any other operation**. A zero result leaves ownership retained. Unexpected ECHILD/ownership errors transition to LOST, cause failure and prohibit signalling. Never infer success from an inability to observe/reap.

Immediately before TERM or KILL, poll through the same owner. If still unreaped, signal only that retained direct child. If it exited between poll and signal, the kernel retains its waitable identity until this sole waiter collects it; no other code in this process can collect it during that interval. This is the safety argument, rather than timestamp uniqueness. Once collection occurs, the object is terminal even if a later spawn receives the same PID. Serialize all operations; no other wait/reap path is permitted. Any spawn API's error-path child collection must also be accounted for. Do not claim Popen alone supplies this invariant.

### Stop requests, deadlines and result

Normal smoke completion, a failed assertion, startup failure, or an interrupt flag calls `request_stop` in the same supervisor. There is no shell-to-supervisor PID signal, FIFO open, socket connect or detached-controller fallback to hang. The foreground runner handles delivered INT/TERM/HUP via its stop flag; tests delivering those signals must themselves retain ownership of the runner until reaping it.

Use monotonic absolute deadlines, not a count of sleeps: issue TERM to every still-owned child first, allow a shared 10-second graceful interval, then issue KILL only to still-owned children and allow a shared 5-second reap interval. Sleep/poll up to 50 ms, capped by remaining time; tests inject shorter deadlines through library parameters. Bounded network/readiness operations must return control to the owner and honor the stop flag; no unbounded pipe reads, inherited-output EOF waits or blocking waitpid. Redirect each child to owned regular log files to avoid pipe-backpressure/descendant-EOF hangs. Bound log/request/response handling and read only a bounded diagnostic tail on failure.

Every child must be reaped with status 0 for normal success. A nonzero child exit, escalation (even if it eventually exits), malformed startup, lost ownership or unreaped timeout fails the invocation. Interrupt exit codes are INT=130, TERM=143, HUP=129; cleanup failures retain failure diagnostics and must not turn an interrupt or earlier failure into success. Repeated stop requests are idempotent and never reset deadlines or signal after REAPED. Collect all children even when one fails; preserve the first failure and report the rest. After successful cleanup, close logs and remove only the invocation's owned workdir with the reviewed physical-path/identity safeguards. Do not introduce weaker deletion checks in the Python migration.

### Failure boundaries the owner must explicitly accept

- On ordinary Python exceptions, assertion failures, missing executable, second-child startup failure and catchable INT/TERM/HUP, run the common cleanup state machine. Install handlers before spawning. Check interruption again after spawn registration and before the next spawn. Create/register each child in a non-reentrant path so no child can be forgotten between spawn and cleanup.
- A SIGKILL, interpreter/native crash, host failure or permanent scheduler suspension of the **supervisor** can leave live model children. Portable Python/macOS/Linux cannot promise both bounded failure and guaranteed orphan removal in those cases without another durable supervisor/kernel mechanism. There is **no PID/ps/process-group recovery fallback**. Document failure and owner inspection when observation is possible; never claim crash-proof cleanup or automatically kill a PID copied from a log.
- If a child remains uncollectible after KILL (for example, a kernel stall), return failure after the configured reap deadline and report that cleanup is incomplete. Exiting may orphan that child. Absolute wall-clock limits cannot be promised when the process is not scheduled or a kernel call stalls; configured deadlines apply to responsive userspace operations, with measured tolerance recorded in tests. Safety takes precedence over attempting an unverified signal.
- Only the directly owned, non-daemonizing mock processes are covered. Arbitrary descendant trees, hostile same-user code, child reparenting tricks, external waiters and inherited SIGCHLD overrides are not supported. Go's build tool and its descendants are not given an automatic kill guarantee by this revision.
- The identity safety invariant is **not** relaxed to best effort: no signal after reaping or on lost ownership. What requires owner acceptance is the explicit limit on always removing every child after supervisor death/unreapable kernel state. If unconditional crash cleanup is required, this proposal is insufficient and execution must stay blocked.
