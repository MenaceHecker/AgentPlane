# Plan P0-T5: Labeled kind environment and local quickstart
Status: DRAFT — owner approval pending; depends on P0-T4
Branch: phase-0/kind
Requirements: NFR-8 (local foundation), NFR-9 (mock-image scanning); requirements section 3.3 placement model (simulation only)

## Goal
Make the documented clean-clone workflow create a labeled local cluster and run the deterministic mock checks. Use a small local topology that distinguishes system and tenant workers without claiming production isolation.

## Out of scope
AKS, Azure, Terraform, GitOps installation, controllers, tenant NetworkPolicy enforcement, real providers, production security or performance evidence.

## Commit list
1. `feat(deploy): configure labeled local kind workers` — `deploy/kind/config.yaml`, `Makefile`; propose one control-plane and two workers, worker label `agentplane.io/pool=system` or `tenant`, with tenant worker taint `agentplane.io/pool=tenant:NoSchedule`. Pin compatible kind/node versions and node image digest; `kind-up` uses this config and explicit name/context. Never silently recreate an existing cluster: validate shape or fail with recovery instructions requiring owner-approved deletion.
2. `build(mockmodel): package and scan local mock image` — `mockmodel/Dockerfile`, `.dockerignore`, `Makefile`, `.github/workflows/ci.yml`; minimal multi-stage nonroot image, pinned base digests, no embedded credentials. Add `make mock-image` (local tag `agentplane/mockmodel:p0`), `make mock-image-scan` (pinned Trivy, HIGH/CRITICAL unfixed findings reported; fail on fixable HIGH/CRITICAL findings; no silent suppressions). Record scanner version, database timestamp, image ID/digest and findings, including unfixed ones. Scan in CI without registry credentials or cloud pushes.
3. `docs(deploy): document clean local setup and recovery` — `docs/local-development.md`, `README.md`; pinned prerequisites and hardware needs, clone/setup, quality checks, default `make kind-up`, explicit context commands, `make mock-smoke`, optional image build/load, named-cluster cleanup approval, failure troubleshooting, local-only limitations. No unsupported Linux/macOS compatibility claims; state tested host and architecture.
4. `test(deploy): record clean checkout acceptance` — `agents/runs/P0-T5.md`; every check below with raw output and actual versions, CI links and missing prerequisites.
5. `docs(docs): update local development progress` — `docs/PROGRESS.md`; READY_FOR_REVIEW after evidence, never mark phase complete or check owner gate on owner's behalf.
