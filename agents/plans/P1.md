## Planned acceptance and exit checks
These targets/harnesses must be specified in the individual plans and implemented before they can be run. They do not exist or have measured results merely because they appear here.

- `git diff --check && make fmt-check && make lint && make test && make secrets && make secrets-history && make secrets-selftest && make contracts-check && make mock-smoke` → exit 0; preserve Phase 0 regression coverage.
- `make manifests && make generate && git diff --exit-code -- api config` → generated files match committed CRDs/RBAC/deepcopies; exact paths/targets confirmed in P1-T1.
- `make test-envtest` → pinned local API-server/etcd integration tests exercise admission, ownership, no-op writes, conditions, finalizers and negative cases. No cluster/provider service required. Exact setup/asset commands supplied by P1-T1/P1-T5 plans.
- `make test-controller-coverage` → write per-controller measured coverage and raw profiles into task run evidence; both controllers at least 70%, without counting unrelated mock/contract packages to inflate totals. Target implementation belongs to P1-T5.
- `make test-drift KIND_CLUSTER_NAME=agentplane-p1` → explicit `kind-agentplane-p1` context; all planned edit/delete scenarios restored under 30s with raw timing evidence and failed cases visible. Target belongs to P1-T6.
- `make test-restart KIND_CLUSTER_NAME=agentplane-p1` → explicit context; leader takeover/restart cases pass with resource inventories and no orphaning. Target belongs to P1-T7.
- Owner exit gate: apply approved Tenant/Agent examples on dedicated kind, confirm the real agent pod is running, inspect namespace isolation objects, measure drift, delete the Tenant with explicit deletion authorization and verify owned-object cleanup, inspect coverage and exact-main CI. Claim actual network isolation only with an enforcing CNI and a separately approved/reviewed connectivity test; object presence alone is insufficient.

## Security-sensitive
Full review required for manager/leader-election code, generated CRDs and RBAC, controllers/finalizers/ownership, webhook reads/admission/TLS/failure behavior, test cluster targeting and workload permissions. No broad secret access, cluster-admin workload role, unsafe foreign-object adoption or cross-tenant owner reference. Distinguish cluster-scoped Tenant authority from namespaced Agent authority. Explicit contexts and owned-resource inventories protect unrelated local clusters.

## Risks and open decisions for individual plans
- Kubebuilder/controller-runtime/Kubernetes compatibility with the current module must be checked against official sources, not guessed; preserve the public API group/version and existing JSON fixtures unless the owner approves a contract change.
- Namespace naming, RBAC subjects/permissions, ownership conflict policy and finalizer semantics need explicit documented choices in P1-T2; no implicit policy for foreign pre-existing resources.
- Webhook deployment/certificate approach for local kind, failure policy and tenant-lookup authorization must be settled in P1-T4. Reuse existing budget-window ADR semantics without building Phase 2 accounting.
- Agent Deployment image/command, tenant taint tolerations, status readiness criteria and deletion behavior must be defined in P1-T3 from requirements; no real model provider.
- NetworkPolicy enforcement/CNI setup is not authorized by this roadmap. Decide explicitly before tests or documentation claim traffic isolation, and assign any extra setup to a task plan.
- No Azure command or cluster deletion is authorized by planning. Obtain explicit authorization for exact disposable names before teardown. Only the owner confirms each phase exit gate.
