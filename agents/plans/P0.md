## Accepted owner decisions
Status: ACCEPTED — recorded from the owner's instruction in this conversation.

- Flux over ArgoCD.
- PostgreSQL (Postgres) for the audit store.
- Hardened pods as the baseline; Kata remains a 2-day timeboxed experiment in Phase 3.
- Fixed daily UTC budget window, resetting at 00:00 UTC. Document the reset-boundary edge case: a caller can consume the previous day's remaining allowance immediately before midnight and the new day's allowance immediately after; a fixed daily cap is not a rolling 24-hour cap. Specify how reservations and streams spanning midnight retain their accounting window so a reset cannot lose or double-count usage; runtime enforcement is later work.
- One audit hash chain per tenant.
- Signed checkpoints containing head hash, count, and timestamp, persisted to a separate store, detect tail truncation against a trusted checkpoint. Bind the signed format to its tenant and define canonical signed bytes, signature metadata and verification rules. Phase 0 defines the format and documentation/fixtures only; it does not implement signing, key management, checkpoint publication, storage, or a runtime verifier. Document that records appended after the latest trusted checkpoint are not protected against tail truncation by that checkpoint.

These decisions are accepted, not awaiting reconfirmation. P0-T2 records them in ADRs; P0-T3 applies them to contracts. Remaining encoding/toolchain details are specification work, not a blanket decision-approval blocker; do not label unspecified choices as owner-accepted.

Specification details such as canonical encoding and toolchain pins remain documented task work. See P0-T2 and P0-T3 for the accepted decisions and contract checks.

## Common acceptance and evidence rules
- Every task records commands, exit codes, tool versions, commit SHA, relevant raw output, and failures under `agents/runs/P0-Tn.md`. Skips, unavailable tools, missing owner decisions, and unavailable CI runs are blocked/unverified, never PASS.
- `git diff --check`, `make fmt-check`, `make lint`, `make test`, and `make secrets` apply once P0-T1 provides them. P0-T0 uses document checks and any installed secret scanner; absent bootstrap tooling is explicitly not applicable. After P0-T3, Go checks must actually execute and must not retain the no-module exemption.
- Tests exercise requirements and negative cases; never delete or weaken tests for a green run. Controllers/gateway coverage targets are not applicable to Phase 0; measured mock coverage is evidence, not a substitute.
- Pin validator/tool versions in repo configuration. Resolve any unavailable/unsupported command through a planner revision, not an executor scope change.
- Any new local cluster must be named explicitly. Owner authorization is required before deleting a cluster; no cloud command is authorized by this plan.

## Owner exit gate after all task merges
Run from a clean checkout of main; save raw output in a subsequent P0-T5 run-report append commit and re-review that evidence if changed. Do not infer success from these planned commands.

1. `make fmt-check && make lint && make test && make secrets` — real Go checks pass; secret scan clean.
2. `make kind-up` then `kubectl --context kind-agentplane wait --for=condition=Ready nodes --all --timeout=180s` — default named cluster exists; all nodes ready.
3. `kubectl --context kind-agentplane get nodes -L agentplane.io/pool` — both system and tenant worker labels present.
4. `make mock-smoke` — starts only the local mock, posts identical input twice, checks identical complete JSON including usage, parses streaming through `[DONE]`, and exits nonzero on mismatch. Implemented and tested in P0-T4.
5. `test -s docs/gateway/openapi.yaml && test -s docs/audit/record.schema.json && test -s docs/audit/hash-chain.md` and the P0-T2 ADR checks — contracts and accepted decisions committed.
6. Inspect GitHub Actions for the exact main SHA: lint, unit-test, and secret scanning jobs green. Record URL and SHA; branch-only success is insufficient.
7. Owner records exit-gate confirmation in progress tracking, with evidence links. Phase 1 remains blocked until that confirmation. Clean up the named local cluster only after explicit deletion authorization.
