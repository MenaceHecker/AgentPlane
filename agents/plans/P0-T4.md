# Plan P0-T4: Deterministic mock model
Status: PLANNED
Branch: phase-0/mockmodel
Requirements: NFR-8/9 (local reproducibility and safe tests); Phase 0 mock requirement; FR-GW-1/8 (test backend support only)

## Goal
Provide a local Go chat-completion backend with deterministic content/metadata, configurable simulated latency, usage, failures, and streaming. All tests and smoke checks run without real model providers, credentials, or internet calls.

## Out of scope
Gateway auth, rate limits, budgets, tool execution, real tokenizer/provider fidelity, platform load benchmarks, cloud deployment.

## Commit list
1. `feat(mockmodel): serve deterministic chat completions` — `mockmodel/{handler,handler_test}.go`, `cmd/mockmodel/main.go`; use the accepted chat subset, deterministic IDs/timestamps/content/usage for identical requests/configuration, strict errors for unsupported requests, bounded request body and server timeouts. Bind loopback by default; explicit listen override for later container use. Add local readiness endpoint and graceful shutdown.
2. `feat(mockmodel): configure simulated usage latency and failures` — `mockmodel/{config,config_test}.go`, handler/tests; documented CLI flags `--listen`, `--latency`, `--prompt-tokens`, `--completion-tokens`, `--error-rate`, `--seed`. Validate ranges at startup. Failure selection must be deterministic from seed plus request rather than mutable global RNG or arrival order. Use injected time/wait functions in tests; respect cancellation. Usage represents simulation, not measured tokenization.
3. `feat(mockmodel): stream deterministic completion events` — handler/stream files and tests under `mockmodel/`; SSE sequence, final usage and `[DONE]` per P0-T3; flush chunks, cancellation, invalid input, and disconnect handling. Non-stream and assembled stream content/usage agree.
4. `test(mockmodel): verify deterministic behavior and lifecycle` — table-driven handler/config/stream tests; same-input concurrency, stable metadata, changed seeds, failure endpoints (zero/all and stable intermediate outcomes), invalid JSON/body limits/method/model, cancellation, server startup/shutdown. No probabilistic pass/fail assertions or long sleep-based tests.
5. `chore(mockmodel): add local run and smoke commands` — `Makefile`, `scripts/mock-smoke.sh`, `docs/mockmodel.md`; add `make mock-run` and `make mock-smoke`. Smoke starts a disposable server on an available loopback port, waits for readiness with a timeout, compares full responses, parses streaming framing and terminal event, and cleans up only its own process via trap. Add real smoke execution to CI.
6. `docs(agents): record P0-T4 checks` — `agents/runs/P0-T4.md`.
7. `docs: update mock progress` — `docs/PROGRESS.md`.

## Security-sensitive
Yes: body limits, loopback default, timeout/cancellation handling, no external provider traffic, secret-free fixtures and bounded resources. Mock is not an authenticated production server; keep local exposure explicit.

## Risks and open questions
The planned deterministic failure rule and stable metadata preserve reproducibility; a random per-request failure generator would break identical-input determinism. Test behavior against published P0-T3 fixtures; do not alter the gateway contract to fit the mock. Image packaging is deferred to P0-T5, with Trivy there.
