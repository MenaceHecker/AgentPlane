# Plan P0-T3: API and audit contracts
Status: DRAFT — blocked on accepted P0-T2 decisions and owner approval
Branch: phase-0/api-contracts
Requirements: NFR-8/9 (foundations); section 4; FR-CTL-5/6, FR-GW-1–10, FR-AUD-1–5 (contract coverage only)

## Goal
Define versioned Tenant/Agent Go types, the gateway OpenAPI contract, and an auditable record/chain specification. Test serialization and contract consistency before runtime implementations exist.

## Out of scope
Kubebuilder scaffold, generated CRD YAML/admission validation, controllers, webhook, gateway server, audit database/library/CLI, enforcement and performance claims.

## Security-sensitive
Yes: identity, reservation/stream semantics, audit encoding/anchors, data retention, schemas and workflow dependency changes. Cross-tenant identity must never derive from request-body identity fields. Audit credentials and actual database setup remain out of scope.

## Risks and open questions
Block execution until P0-T2 choices are accepted, including Go module/toolchain. Preserve future Kubebuilder compatibility without pulling Phase 1 scaffolding forward. Any schema change conflicting with requirements needs owner resolution before implementation. Contracts must not imply default kind CNI or type declarations enforce isolation or budget caps.
