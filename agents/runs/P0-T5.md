### Finding 1: process identity (`scripts/lib/owned-process.sh`)
What was wrong: ownership was checked once before SIGTERM; after polling, SIGKILL went to the same PID with no recheck; `OP_REAPED` is helper bookkeeping, not proof the PID cannot be reused (bash can collect an async child before `wait`).
Fix: each registered child gets an **identity token**, its start time as `ps -o lstart` reports it, captured at registration (a child whose identity cannot be established is not registered). A probe returns RUN, EXITED, CHANGED or UNKNOWN: the PID must still be a child of this shell with the registered start time. It runs at every poll and **immediately before each signal**; TERM or KILL is sent only on RUN, and a changed or unknown identity means no signal, no escalation, a diagnostic and status 1.
Tests (a `ps` wrapper only the library uses can report a different owner or start time at chosen moments; an unrelated live canary with the same command line must never be signalled): owner differs at the first probe; owner differs between the first probe and SIGTERM; owner changes after SIGTERM while polling (no escalation); owner changes in the ps call made immediately before SIGKILL; a PID-reuse model (our child really exited, an unrelated process holds the PID); and a control where nothing changes and the TERM-ignoring child is killed. RED against the previous library (its two mid-stop cases sent SIGKILL):
```
FAIL  identity at first probe (rc=1, signals=0): owned-process: refusing to signal idtest1 (pid 91613): it is not a child of this shell
FAIL  identity change while polling (rc=1, TERM=1 KILL=1): owned-process: idtest2 (pid 91653) did not exit within 400 ms of SIGTERM; sending SIGKILL to that process
FAIL  identity change before KILL (rc=1, TERM=1 KILL=1): owned-process: idtest3 (pid 91990) did not exit within 100 ms of SIGTERM; sending SIGKILL to that process
PASS  identity (control): with an unchanged identity the same TERM-ignoring child is escalated and killed
owned-process self-test: 3 FAILED
```
**Residual limit, stated plainly, and a proposal that needs your decision.** Between the last probe and the `kill` system call there is a window of microseconds that no PID-based check can close: in theory the child could exit, be collected by bash and the PID be reused in that window. The window is narrowed (identity plus the shell job table are re-read immediately before the signal) but not eliminated. The bash source is not reachable from here (the GNU and GitHub URLs returned 404 or a redirect), so I did **not** rely on any claim about bash's internal guards against recycled PIDs.
Proposal to remove the window, **not implemented, owner/planner approval needed** because it changes the design: (A) run each owned child under a small supervisor (for example a Python process, itself the shell's direct child) that holds the child through `subprocess.Popen`, which cannot signal a collected process, and accepts "stop" over a pipe or FIFO, so the shell never signals a child PID at all and only signals the supervisor as a last resort; cost: one more process per server, a small protocol, a python3 dependency (already required by the smoke script). (B) A kernel handle (pidfd) on Linux, which macOS lacks, so it cannot be the portable answer. (C) Accept the window as documented. I recommend A if zero residual is required, C otherwise.

### Finding 2: no wait on an unknown state
What was wrong: an empty or failed `ps` answer was treated as "exited" and a bare `wait` followed. The reviewer's probe: with the state query failing and a child that never exits, `op_stop` sent nothing, waited for the child's whole lifetime and returned success.
Fix: observation is corroborated by **bash's own job table** (`jobs -r -p`), which records the children this shell started and has not collected; a recycled PID cannot appear in it and a failing or lying `ps` cannot change it (I verified on bash 3.2.57 and 5.2.37 that `$(jobs -r -p)` works in a command substitution and that exit statuses survive `jobs`). EXITED, the only outcome that permits a wait, requires a zombie, or agreement between ps (no such process) and the job table (not running). RUN, the only outcome that permits a signal, requires ps and the job table to agree. A failing ps, a successful ps with no output, an unreadable job table or any disagreement is UNKNOWN: no signal, no wait, a diagnostic, status 1; nothing is left unreaped without saying so. Registration requires the child to be in the job table.
Tests: a long-lived child (it would run 600 s) with an outer watchdog (owned by the test, it kills only that child after 6 s) so a regression becomes a failed assertion, for: ps failing, ps with no output, ps saying "no such process" for a live child, an unreadable job table, a job table claiming the live child finished, an exited child with an empty ps, a refused registration (ps failing), a disowned child, and an EXIT cleanup that cannot read the process table (bounded, status 1, directory removed, child left alone). ### Blocked: process-ownership design decision for finding 1 (owner/planner)
The plan (`agents/plans/P0-T5.md`, item 1) requires "never signal a reaped PID, arbitrary process, or process group".
