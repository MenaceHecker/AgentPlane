## Limitations
- The cluster was tested on **macOS arm64 with Docker Desktop only.** CI creates **no kind cluster**; Linux and amd64 cluster creation are untested. CI runs the stub tests, the image build, the container checks and the scan on linux/amd64.
- Labels and the tenant taint are placement simulation, **not tenant isolation**. I ran no scheduling test; no isolation, NetworkPolicy or Pod Security claim is made.
- The Homebrew kind binary reports v0.31.0 but its SHA-256 differs from the upstream release asset; the script enforces the version, not a binary hash.
- The single create from the clean clone took 28 s wall clock (one run, not a benchmark); the cold-cache node-image pull time was not isolated.
- The scan is a point-in-time result against the database downloaded at scan time, and only the mock image was scanned.
- The owned-process helper counts nominal milliseconds per poll, so real elapsed time can exceed the nominal deadline by the cost of each poll. Tests use injected short deadlines; the only fixed waits are short `sleep` settling pauses (0.05 to 0.3 s).
- `go build` inside `scripts/mock-smoke.sh` is not time-bounded (it is not an owned long-running child); CI has an outer job timeout.
- kubectl v1.36.0 was used against a v1.35.0 cluster (one minor version of skew, supported).
