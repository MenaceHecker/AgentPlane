## Security review

**Scope.** a18b68d implements regular-file stdin/separate stderr and Workdir.open_read; dd5b307 implements the persistent kind owner/exec wrapper; df8a840 tests raw cleanup/context success and updates docs/ADR. These match the r4 three-commit scope selected by Codex and subsequently owner-approved. No in-memory-only cleanup alternative, shell pipeline, Go checker redesign or cloud capability was invented. Echo byte caps, optional test timeout and fixed per-command timeout choices are implementation details within that scope. The raw HTTP/1.0 client preserves the Go mock's response-body/SSE checks; real smoke runs exercise it.

**Ownership/state.** Normal paths remain a single parent/waiter/signaller, with SIGCHLD default, no async reaper, no waitpid(-1), no group signal, opaque identity checks and flag-only INT/TERM/HUP masked through registration. NEW is visible but not signalable; REAPED is written before decoding and never waited/signalled again; ECHILD/failed signals produce LOST with a reason and prohibit signals. Emergency recovery now polls immediately before KILL through the same path, and uncollectible recovery stays visible. Smoke and kind gates require every child state equal REAPED, not merely done, so LOST/NEW cannot permit removal. Finding 1 is the remaining exception-safety gap, not a reason to relax those gates.

**Command IO.** Owned duplicates are non-inheritable; stdin is null or a validated regular file, stdout/stderr are exclusive or validated regular append/readwrite captures. Workdir.open_read uses a single manifest name, no-follow open relative to the held child, recorded live-file identity, and a new read-only file description starting at zero. No pipe is passed to a command or awaited for EOF. Child exec closes fd range 3..min(SC_OPEN_MAX,65536); an explicitly inheritable unrelated fd above that cap is an existing containment limit, so this review does not claim arbitrary-launcher fd isolation. Ordinary Python-created fds and all library/workdir fds are non-inheritable and tested.

Echo is capped at 4 MiB per stream, captures used for diagnostic tails at 1 MiB. The owner's terminal writes/flushes are synchronous: if its own stdout is a non-draining pipe or a filesystem/kernel call stalls, the owner can block despite the command IO being regular files. Configured command deadlines therefore assume responsive owner IO/scheduling, as with the documented kernel-stall boundary; a byte cap is not a nonblocking-write guarantee. Do not advertise unconditional wall-clock cleanup or pipe-backpressure immunity. Oversized machine-readable captures should eventually fail explicitly rather than silently relying on a tail; no such oversized case was exercised here.

**Kind semantics.** Every create/delete/export has --name self.name; node reads use --context kind-NAME. Preflight docker/version calls precede context capture but perform no context mutation. A prior context is accepted only after a successful config-view command; failed reads never mean empty. Existing clusters are checked rather than recreated/deleted. Missing context triggers export only after a successful contexts listing. Down changes desired restoration to empty only after successful deletion when prior==deleted context. Restoration runs even after catchable interruption with honor_interrupt=False, reads before and after use/unset, and verifies actual state rather than trusting a write command's status. A failed write that nevertheless achieved the desired state is accepted only after successful readback, matching earlier behavior. Final code preserves prior nonzero statuses/signals, flags LOST/unreaped/force-killed children, records output failure, closes descriptors, and cleans only if all are REAPED. No lost/NEW/output failure path found can yield 0.

**Workdir.** Existing held parent/child/file reference, manifest verification, no-follow and nonrecursive parent-relative rmdir semantics are preserved. The checker binary is adopted only as fixed kindshape after successful build. Root replacement and unknown files retain evidence and preserve decoys; the final rmdir race and hostile-same-user verify/unlink limit remain explicit. This is not hostile-same-user filesystem containment. Go/kind/tool descendants remain outside the direct-child guarantee; no crash/orphan recovery by rediscovered PID is authorized.
