## Security review

**Process safety.** Only registered positive numeric PIDs are used in normal signals and no group/name matching is used. TERM/KILL polling and shared EXIT/INT/TERM cleanup work in baseline cases. The remaining races/unknown-state wait in findings 1–2 invalidate the stronger unreaped/owned-only/bounded guarantee. A harmless independent /bin/bash probe confirmed a short-lived child had disappeared from the process table before explicit wait, while wait still returned its cached exit status 0; helper bookkeeping does not prevent OS PID recycling. The helper uses Bash-3.2-compatible constructs and the local Bash is 3.2; normal tests pass on the tested host, which is not a proof against every scheduling race. Leaf-symlink, relative and '..' refusals remain conservative; no outside deletion was observed. Multiple slash normalization is a safe refusal/leak, not an observed traversal deletion. go build remains explicitly unbounded as disclosed.

**Cluster safety.** No real kubectl or kind operation was executed during review, and no cluster was created/deleted. Server-facing calls in the script specify --context; unqualified config subcommands are local kubeconfig operations, not server requests. up never invokes delete/recreate and only creates when its named cluster is absent. The name/config arguments are quoted within the script, but the Make entry point is unsafe (finding 3). KIND_CONFIG selects an operator-controlled file; KINDSHAPE_BIN intentionally executes an operator-controlled checker and must be treated as trusted, like PATH, not as sanitized untrusted input. Restoration fails open (finding 4). down normally only removes the named cluster's entries: an unrelated current context stays unchanged; if the deleted cluster itself was current, no valid prior context remains to restore, so blanket unchanged-context wording needs that qualification.

The checker derives node count/role/pool/taint/version from a restricted config and rejects missing tenant taint, wrong effects/labels and version mismatches. It is read-only and reuses existing Go/Kubernetes/YAML dependencies; technically reasonable, but the owner still decides the scope addition. It does not prove scheduling/isolation or validate the provenance of an arbitrary alternative digest. The committed image digests are identical; contrary to a documentation claim, merely passing the digest regex/version checks does not independently prove all supplied config digests are identical.

The [kind v0.31.0 release notes](https://github.com/kubernetes-sigs/kind/releases/tag/v0.31.0) confirm the pinned 1.35.0 node digest and the still-v1beta3 kubeadm patch expectation. The versioned worker JoinConfiguration nodeRegistration taint is appropriate for that pin. Live application was not rerun; the report is the evidence for that past run, not current independent proof.

**Image/scan.** Docker manifest inspection confirms both pinned bases are OCI indexes with amd64/arm64 entries. The built image uses the minimal static distroless runtime and numeric nonroot user; the runtime COPY contains the compiled binary only, and the allowlisted context excludes root secrets/DOCX/tests. Hardened startup passed. Local Docker's manifest image ID is `sha256:0793ad23d1dc95569240a8dd4930f480abc969da5d6f8f5358ce8a8622b34e2d`; Trivy reports the separate config digest `sha256:e2858bf3c0ab64ee48c76195b3323464b24bba8d8d84ca85122a115ac97462e9`, matching the report. Cached rebuild equality does not prove universal bit-for-bit reproducibility.

The script fails closed on observed scanner/database errors, missing/empty/invalid JSON, no package target and version mismatch, retains full findings and rejects suppression config/environment. FixedVersion-present HIGH/CRITICAL fail regardless of will_not_fix/end_of_life Status; empty fix versions are treated as unfixed, with the contradictory-status caveat in finding 6. No silent omission was observed in the real scan. DB v2 updated 2026-11-25T13:07:24Z was already cached and fresh; this review did not retest a real network/database outage or download a cold database.

Official advisories confirm the selected Trivy pin is beyond the affected/fixed versions: [supply-chain incident](https://github.com/aquasecurity/trivy/security/advisories/GHSA-69fq-xp46-6x23), [artifact traversal fixed in 0.71.1](https://github.com/aquasecurity/trivy/security/advisories/GHSA-mcj4-mphf-j9ff), and [plugin traversal fixed in 0.72.0](https://github.com/aquasecurity/trivy/security/advisories/GHSA-8rc5-4fr6-64pw).
