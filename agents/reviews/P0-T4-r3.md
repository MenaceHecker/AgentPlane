## Security review

The parser normally bounds expansion by a 16-digit guard, but unchecked signed arithmetic defeats it at exact limits. Request-body limits do not mitigate a numeric field only a few dozen bytes long. Existing net/http panic recovery prevents the observed request panic from terminating the server; it does not provide the promised JSON error or validate resource safety. Fix the arithmetic rather than relying on recovery. No successful allocation proportional to these extreme exponents was observed; the demonstrated failures are allocation/count panics.

The oracle control uses fixed stub statuses and resets DETECT to the real detector before actual integration cases. Only exit 1 returns a candidate; 0 retries, other statuses produce setup error 2. This validates wrapper behavior against the pinned detector, not exhaustive secret detection. The production scanner/configuration is unchanged in this round.
