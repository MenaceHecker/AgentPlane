Finding 1 evidence is a controlled PID-reuse **model**, not a claim that I forced kernel PID reuse. Two actual children of one scratch shell had identical `lstart` strings. After the first exited, I retained its identity token and mapped its stale registry PID to the second child to model reuse of that number. Unmodified probe/signalling logic produced:

```text
same-second replacement: PROBE=RUN
DRY-RUN SIGNAL -TERM <replacement-child-pid>
signal_result=0
```

The signal function was intercepted; the replacement was then stopped separately by its actual owner. No foreign process was signalled. A numeric-PID job table cannot distinguish these model states.

Finding 3 used only the committed stub tools copied into a scratch archive, extended with read failures, plus a no-op checker stub. Both scenarios returned 0 and printed `<none> (verified)`; the stub state files showed respectively an erased prior context and a remaining kind context. No host kubeconfig or cluster was touched.

## Security review

- **Process ownership/reaping:** unknown/contradictory observations now refuse signals and waits; both signals re-probe; already-recorded reaps return their stored results. These address the demonstrated r1 failures, but do not establish unique identity (finding 1). The proposed supervisor is neither implemented nor approved here; its own lifecycle and fallback signalling would need review.
- **Filesystem cleanup:** repeated/trailing slashes and spaces now normalize consistently, and leaf symlink/parent-reference tests remain. A root spelling of `/` normalizes to `/`; I did not create test directories at filesystem root. Ancestor retargeting remains unsafe (finding 4). Parent-reference paths fail closed but may leave their own created directory behind. This is not a general defense against an attacker controlling the same user's filesystem.
- **Make boundary:** no new shell eval was introduced; listed variables reach quoted environment arguments, and ordinary flags still work. The remaining recipe Make expansion is help's `$(MAKEFILE_LIST)`, which belongs to the trusted Makefile/flag boundary. Supported data variables outside the capture list remain exposed (finding 2). Arbitrary Make flags/Makefiles and executable `KINDSHAPE_BIN` selection cannot be promised harmless independently of that boundary.
- **Cluster targeting/context:** all server operations remain explicitly targeted; local config operations use stubs in this review. The EXIT trap is installed before create/export/delete. Down's successful deletion of its own prior context correctly requests no current context afterward; other contexts are restored. Failures before trap installation have not yet performed a context-changing operation. Read errors still invalidate the preservation guarantee (finding 3).
- **Scan gate:** fixed-status/blank-version evidence now exits 2. Nonempty fixes fail HIGH/CRITICAL regardless of will_not_fix/end_of_life, while genuinely unfixed findings remain listed. No new suppression path found. Scan wrapper validates image/version before tools, and propagates scanner/database/report errors.
- **Scope:** mock-only HTTP tests, no provider calls, Azure/cloud commands, registry pushes or cluster lifecycle commands. The DOCX, plans and gateway contract were not modified. Go-toolchain/CVE-2026-97054 and the added Go-checker decision remain owner decisions; a green gate does not approve either.
