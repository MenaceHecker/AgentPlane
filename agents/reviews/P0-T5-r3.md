## Test review

These tests substantially exercise requirements: fake adapters model identity reuse, retained zombies, ECHILD, failed kill, foreign/copied handles, idempotence, shared deadlines and uncollectible states; real children cover clean/nonzero/early exits, actual escalation, missing exec status 127, signal dispositions, session setup, logs and canary survival. The replacement model does not pretend to force real kernel PID reuse. Adapter identity tests cannot signal foreign real processes.

Gaps: no assertion of immediate wait/kill adjacency at both TERM and KILL, no assertion that REAPED is set before a deliberately failing status decoder, no post-fork parent exception test, no FIFO/regular-descriptor test, no timeout with TERM ignored in the repeat utility, and no smoke-runner phase-specific signal/second-spawn tests because that runner is unimplemented. The repeated-stop test observes a completed child; a longer timeout argument on an already terminal handle is weaker evidence than reentry while cleanup is still pending. Add deterministic pending-state tests rather than treating successful repetitions as proof of all failure boundaries.

The 10/10 and 4/4 default commands execute **29 ownership-library tests per run**, not the Bash filesystem suite or migrated smoke. Linux's 10/10 claim has the same limited scope. The plan now requires explicit `-- make smoke-cleanup-test` and smoke runs after migration. Existing replacement assertion was not weakened in these commits.

## Security review

Library guarantees inspected against `scripts/lib/owned_process.py`:

- Sole waiter: PosixAdapter uses only positive child-specific WNOHANG waitpid. No Popen, async watcher, SIGCHLD reaper, waitpid(-1), external PID or group signal in the library. Owner methods rely on the documented single-threaded caller; constructor checks main-thread creation, not hostile subsequent callers. Treat opaque handles/private attributes as an API contract, not a sandbox against Python introspection.
- Handles: exact type, registry object identity and owner identity required. No public PID accessor or PID-taking stop API; copied/foreign handles fail. Completed requests return false and never signal.
- Reap ordering: state becomes REAPED before decode_status; terminal handles never wait again. ECHILD/other wait errors and failing kill calls set LOST and prohibit subsequent signalling. LOST is failure, never successful observation.
- Both TERM and KILL call the same _signal path, whose poll precedes the positive-PID kill. With this owner as the sole waiter and SIGCHLD default, an exit in that gap retains kernel identity. This argument does not apply to the still-active Bash helper.
- Deadlines: one shared absolute graceful deadline per Owner, then one shared reap deadline; repeated shutdown does not reset either. The reap interval begins when escalation is initiated. Owners reused for future independent batches inherit old deadlines; callers must define their lifetime accordingly. request_stop alone does not start an escalation timer (the repeat runner misuses it; finding 2).
- Signals/spawn: SIGCHLD default established before spawn; INT/TERM/HUP handlers only retain first signal. They are blocked from before fork through registration and mask restoration. Child resets dispositions, unmasks, setsid, redirects stdio, closes descriptors and execs argv with no shell. Exec/setup exception attempts bounded diagnostics then _exit(127), verified for missing executable. Parent exception registration gap remains finding 5. Descriptor closing caps at 65536; do not describe this as a general hostile-fd containment boundary. Logs and workdirs need finding 4's fix.

ADR-007 is honest about **Accepted / Proposed / Open** against the plan's actual quote “I approve, commit, push and merge with main”: accepted migration, stated crash/unreapable limits and added files; implementation details proposed; workdir identity open at the reviewed head. A merge direction is not a technical verdict and the latest owner correction says nothing merged. The r3 selection is a Codex follow-up decision, not a fabricated new owner quote. Its broad “always” phrasing should be read with the explicit limits; executor should qualify it when updating ADR-007. The fixed parent-fd plus allowlisted-file decision and Bash refusal policy are in the revised plan, with explicit final-rmdir race limits. No atomic fd-only rmdir is claimed.
