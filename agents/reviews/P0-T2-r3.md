## Security review

Unknown consumption now charges a validated maximum, and the slot follows execution uncertainty rather than reservation terminal state. This closes the prior refunded-consumption path under the stated assumptions. Provider completion/abort acknowledgements must actually prove execution has ended; a transport disconnect is not that proof. The execution deadline must be implemented against the same forwarding-time basis and protected against delayed dispatch and clock errors; that belongs in the stated boundary/conformance tests before runtime guarantees are claimed.

The signed checkpoint format remains consistent and tenant-bound. Audit entries remain append-only, with keys and checkpoint anchors outside the audited database. The new `correction_pending` obligation is an improvement for crash recovery, but its producer update and audit delivery must preserve durable, idempotent event identity. A retry policy without append deduplication can corrupt semantic usage totals while preserving cryptographic linkage (finding 1).

Logical request counting via distinct request IDs is appropriate; checkpoint counts correctly refer to physical entries. Incomplete-trail anomalies are distinguished from hash-chain breaks. Rejected-request logging during an audit outage remains an explicit completeness limitation, and admission-only fail-closed does not retract already-delivered streaming bytes.
