## Security review

The 1 MiB body limit reads max+1 bytes and correctly returns 400 invalid_request rather than 413; exact-limit/one-over tests pass. Read/header/idle/write timeouts and a header-size cap are configured. Default listen is 127.0.0.1; non-loopback or wildcard binding requires an explicit listen override. No production auth is claimed. The documented executor choices (zero prompt means derive, completion 0..10000, latency 0..30s, config error exit 2, arbitrary model name, simulated 500) are reasonable mock choices except the aggregate domain bug and byte/character mismatch; they are not owner-approved architectural decisions.

WriteTimeout is an absolute 60-second deadline, not a per-event timeout. There is one simulated wait of at most 30 seconds before the stream, followed by immediate bounded event generation; there is no per-token latency to multiply by 10000. A slow consumer can still exceed the deadline and receive a truncated stream. This is a safety bound, not a promise of successful delivery to arbitrarily slow clients. Event lists are precomputed, so cancellation does not avoid that bounded allocation; context checks stop subsequent writes, and write failures stop the loop. No global connection/concurrency cap exists, so total resource use remains unbounded with unbounded clients. Acceptable only for the explicitly local controlled backend; resource/admission controls must be revisited before untrusted exposure. No load or performance result was measured here.

Serve grants five seconds for in-flight drain; on timeout it returns an error, without force-closing remaining connections itself. The command then exits nonzero. Documentation that an in-flight request finishes should be read with that limit; reusable embedded-server shutdown cleanup merits later hardening. 404 is the ServeMux default plain-text response on an unsupported path, not the JSON envelope claimed in the handoff's weakest-items list. 405 uses invalid_request with Allow. These method/path responses are outside the declared POST operation and do not require changing gateway contracts.

Smoke binds OS-assigned loopback ports, captures only its own child PIDs, verifies normal SIGTERM status, scopes temp removal to its mktemp path and reports request/schema/process failures. Its unbounded waits are recorded in finding 4. No broad process kill is used. Go/curl/python3 are checked and available in the verified Ubuntu CI runner. Builds may need dependency downloads on a fresh cache; runtime requests and tests do not call a provider. No credential/environment lookup or external service client exists in product code; test clients use loopback. Fixtures are synthetic and secrets scanning passed.
