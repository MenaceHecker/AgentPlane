## Test review

The suites exercise real obligations, not only implementation details: deterministic fake identity reuse and retained zombies, wrong/foreign handles, immediate wait-before-TERM/KILL ordering, REAPED-before-failing-decoder, ECHILD and failed kill, regular-fd validation, unlinked log reads, held-directory replacement/inode reuse, unknown entries and symlink refusal, actual child TERM/KILL/statuses, failed second spawn, readiness failures, interrupt phases and concurrent loopback ports.

The retired-Bash inventory matches the substantive obligations in the diff: normal/nonzero/early exit, escalation timing and failure, terminal-handle refusal, identity replacement models, uncertain-observation refusal, foreign handles, canary survival, partial startup and INT/TERM are represented. Removal of ps/jobs tests is justified by removal of that API; ECHILD/kill-error cases retain the failure obligation. HUP is added. The post-stop liveness requirement is strengthened by observed REAPED statuses plus the HTTP check. No foreign-signalling regression was found on the normal registered-handle path.

**Bash assertion decision:** accepting “not the directory that was created” OR “is not empty” is acceptable. It changes the reason the operation refuses, not the required safety result: the operation must fail and the replacement's decoy file must still exist. The additional identity-collision case directly exercises the nonempty refusal. Changing the positive deletion fixtures to empty directories is justified by the new contract, and separate nonempty retention checks remain. The Bash path does not claim empty-directory identity is race-proof; it may remove an empty replacement under the disclosed boundary, but cannot recursively remove replacement files.

**SIGKILL limit:** the test correctly avoids promising supervisor self-cleanup and never signals rediscovered orphan PIDs. Fake servers have a self-exit watchdog. However, absence of a cleanup report is not alone proof of a surviving orphan (finding 8). Likewise the in-process LOST test deliberately makes observation fail for a real child and waits for its watchdog/port closure; it does not reestablish kernel collection. Treat these as bounded model fixtures with explicit limits, not universal no-orphan proof.

Missing failure coverage is material: uncollectible repeat command; completed+fresh default shutdown; failed emergency recovery; diagnostic/output failure; slow HTTP progress and invalid deadlines. Existing passing tests do not cover those combinations. The concurrent repeat's printed tests=None is a reporting limitation: its parser only recognizes a line beginning “Ran”; the shell suite wraps four such summaries. Counts are visible in the suite logs, not in the repeat summary.

## Security review

**Filesystem.** Workdir.create anchors physical parent and new mode-0700 child using live descriptors, directory/no-follow flags and no path fallback. create_file exclusively creates a single component and retains its file identity. _verify rejects replacement child, changed physical parent, missing/replaced/nonregular manifest file and unknown entries before cleanup; unlinks go through the held original child fd. rmdir is a nonrecursive operation on the basename relative to the held parent. Non-inheritance is enforced by CLOEXEC/modern Python dup behavior and tested. A replacement directory present before verification is never traversed or unlinked; even the injected identity-collision case can only rmdir a replacement, whose nonempty decoy makes it fail.

**Compiler adoption.** adopt_file is an explicit trusted-caller exception to exclusive creation, not recursive adoption of discovered names. Smoke adopts only fixed “mockmodel” after the owned go child is REAPED with exit 0; the file must be regular/no-follow, opened relative to the held original directory, and its fd is retained. It does not prove cryptographic compiler provenance or reject hardlinks; same-user hostile replacement is outside the boundary. Under that stated trust model this is acceptable and does not redirect cleanup to another directory. Add a replaced-root-before-adoption regression to protect that assumption in future changes.

**Race honesty.** The final stat/rmdir race is stated accurately: POSIX provides no atomic compare-and-rmdir by the child fd. A nonempty replacement survives rmdir. This is not protection from all same-user concurrent mutation: an adversary can also replace an individual manifest entry between verification and unlink in the held directory. The global hostile-same-user exclusion in ADR-007 covers that, but “a replacement's files are never touched” must be read within that exclusion. No claim of atomic verification/deletion is approved. Setup/open failures may retain a newly created directory, which must be reported rather than recursively removed.

**Supervisor.** For registered children, sole waiter, opaque handle identity, SIGCHLD default, flag-only handlers, masking through fork-to-register, no shell/Popen/async reaper/waitpid(-1)/process-group kill remain intact. poll marks REAPED before decode; terminal states disable future waits/signals. _signal polls immediately before TERM/KILL; Owner.interrupt permits only INT/TERM/HUP, verifies the exact owned handle and polls immediately before delivery, leaves shutdown state intact and fails LOST on signal error. Exec failure still exits 127. Emergency recovery is the exception requiring finding 5. Per-child deadline storage is appropriate, but aggregation must be fixed (finding 3).

**Smoke cleanup.** Normal/failure checks converge on shutdown; catchable signal codes 130/143/129 preserve the first signal and cleanup failures do not yield success. Workdir cleanup is gated on every recorded child being REAPED; LOST/uncollected states retain it. That gate is insufficient until an unregistered failed-emergency child is represented, and cleanup itself must run despite output errors. Go compiler descendants remain outside the accepted direct-child guarantee. No model-provider call was introduced.
