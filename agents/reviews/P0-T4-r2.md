Naming errors also detects mutations that are rejected later for another reason; it should not be mistaken for an additional security rejection. Independent temporary-overlay probes (repository tests/code untouched):

- Missing content, null content, null temperature/top_p/max_tokens/stream/stop, null message element, nested stop nulls, unknown members and valid empty content were compared with the unchanged schema in plain and stream variants. Original r1 cases agree with the schema now. Duplicate members follow the same last-value-wins behavior as the Go schema loader; valid-last is accepted and null-last rejected. Huge numeric values, BOM and trailing data are rejected. Decimal/exponent integer spellings expose finding 2.
- Repeated malformed requests expose finding 1; the probe fails its full-body equality assertion. Successful-response determinism was not regressed by these probes.
- Additional accepted configurations at prompt counts 0, max-10000, max-16, max-1 and max, completion counts 0/1/16/10000, and omitted/small/maximum max_tokens produced schema-valid JSON and SSE usage. The aggregate guard uses subtraction after component checks, avoiding addition overflow. Derived word counts are bounded by at most 16 MiB of input and completion at most 10000, far below 2^53-1. This argument applies to validated configurations; NewHandler itself still assumes a validated Config.
- Actual JSON-escaped surrogate pairs at 128 code points are accepted, at 129 rejected. Unpaired escaped surrogates and raw invalid UTF-8 are accepted/replaced by Go's JSON decoder, as they are by the Go schema-validation path. Thus these probes show agreement with that oracle, not strict Unicode-wire validation or cross-language parser equivalence.

The committed cases named "escaped surrogate pairs" in `mockmodel/model_length_test.go` actually repeat literal emoji, not JSON backslash-u escape text. They duplicate the four-byte cases. My independent escaped-input probe passed, but the report overstates committed coverage for escaped forms; replace those fixture strings with actual escapes when updating the tests/report.
